##  项目经历

<div class="entry-title">
    <h3>知享-知识获取与分享社区</h3>

</div>

后端 & 前端开发（前端采用 AI 辅助开发）

- **项目概述**：知识社区 APP（后续考虑支持付费），支持发布知识、点赞/收藏、关注取关、首页 Feed 展示与对象存储直传，AI 生成摘要等等。项目各模块进行了充分详细的设计以满足高并发和高可用需求
- **主要技术**：Java 21 + Spring Boot + Spring Security + MyBatis + MySQL + Redis + Kafka + Caffeine + 阿里云 OSS + Lua;
- **项目细节与亮点**：
  ### 认证系统：RS256签名与双令牌安全闭环
- 安全会话管理：基于Spring Security构建**JWT双令牌**（Access/Refresh Token）体系，采用**RS256非对称加密**确保令牌防篡改。
- 即时撤销机制：在Redis中维护**刷新令牌白名单**，实现15 mins短效访问令牌与7天长效刷新令牌的平衡，支持**异常时强制踢离**。
  ### 二值行为存储：高性能分片位图方案
- 二值行为存储：针对点赞等二值行为，采用Bitmap分片存储，用户ID映射到位图位置，0/1标识行为状态，实现O(1)查询。
- 分片优化：通过Bitmap分片设计分散热门内容的读写压力，支持并行统计；位图作为长期行为事实存储，可用于计数重建，避免单一大Key带来的Redis阻塞风险。
  ### 计数系统：定制化 SDS 存储 + 异步聚合刷写架构
- **SDS 定制存储**：基于 Redis SDS 设计自定义二进制存储结构，通过固定偏移量封装多维度计数（点赞/收藏等），替代 Hash 存储方案；利用偏移读写直接更新计数值，减少对象与字段开销，降低内存占用，访问延迟显著降低。
- **异步聚合刷写**：构建“事件解耦 → 增量聚合 → 原子刷写”的计数更新链路：用户行为事件（点赞/收藏）通过 **Kafka 异步传输**，在 Redis 中按内容 ID 聚合增量；后台刷写任务按秒扫描活跃聚合桶，通过 **Lua 脚本**原子执行「**读取增量 → 更新 SDS → 清空聚合字段**」，避免高并发写放大与热点 Key 阻塞问题。
- **位图重建自愈**：当计数缺失或结构异常时，系统自动触发**位图重建机制**：加**分布式锁**避免并发冲突，并行扫描行为 Bitmap 分片统计真实用户行为，再原子修正 SDS 计数值，确保长期数据与真实行为保持一致。

### Feed流：三级自适应缓存架构与流量防护

- **多级缓存架构**：设计 **L2(Caffeine 本地缓存)** → **L1(Redis 页面骨架缓存)** → **L0(内容条目碎片)**\*\* 的三级缓存体系，将静态内容与动态计数解耦，提升内容复用率并降低缓存失效率，显著提升 Feed 流响应性能。
- **个性化数据隔离**：用户点赞、收藏等个人态不写入公共缓存，在响应阶段通过 Bitmap 行为查询动态叠加，避免污染共享缓存，保证高缓存命中率与数据一致性。
- **流量防护机制**：构建完整缓存保护体系：
  - 缓存雪崩防护：TTL 引入随机抖动，分散缓存集中失效；
  - 缓存击穿防护：通过互斥锁控制回源，仅允许单请求访问数据库，其余请求复用缓存结果；
  - 缓存穿透防护：对不存在内容写入 **NULL 占位缓存 + 短 TTL**，避免无效数据库访问。
